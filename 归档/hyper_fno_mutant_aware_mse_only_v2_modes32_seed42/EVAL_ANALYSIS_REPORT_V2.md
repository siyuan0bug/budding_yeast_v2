## 1. 执行摘要

### 1.1 三方对比表

| 维度 | v1+none (baseline) | v2+none | v2+mutant_aware |
|------|-------------------|---------|-----------------|
| **数据集** | v1 (53,796 样本) | v2 (~66,000 样本) | v2 (~66,000 样本) |
| **AL 策略** | none | none | mutant_aware |
| **初始训练集** | 全量 (~53,670 LHS) | 全量 (~65,000 LHS) | **仅 2,000 (K-Means)** |
| **最佳 epoch** | 180 | 197 | **12** (极早停止) |
| **val_loss_lhs** | 0.0291 | 0.0151 | 0.0664 (4.4× 更差) |
| **LHS Test Rel L2** | 0.0912 | **0.0874** ✅ | 0.1846 ❌ |
| **Real Mutants Rel L2** | 0.4131 | **0.2608** ✅ | 0.3902 |
| **Real Mutants MAE** | 0.3600 | **0.1926** ✅ | 0.3754 |
| **cdc20_ts 家族 MAE** | 1.627 | **0.044** ✅ (-97%) | 0.274 (-83%) |
| **Sim-to-Real Gap** | 4.53× | **2.98×** ✅ | 2.11× (误导性) |

### 1.2 核心结论

1. **V2 数据集成功**: V2+none 的 Real Mutants Rel L2 从 0.4131 降到 0.2608（**-37%**），MAE 从 0.3600 降到 0.1926（**-47%**），Sim-to-Real Gap 从 4.53× 缩小到 2.98×。V2 数据集的定向扩展采样（cdc20_ts boundary + cdh1 anchor + 低密度补足）有效缓解了 Sim-to-Real Gap。

2. **mutant_aware AL 反而变差**: V2+mutant_aware 不仅比 V2+none 差（Real Rel L2: 0.261→0.390），LHS Test 性能也暴跌（0.087→0.185）。根因是 **AL 框架的初始训练集仅 2,000 样本**（K-Means 选取，仅占全量 3-4%），导致模型严重欠训练，最佳 epoch 停在 12（vs V2+none 的 197）。

3. **V2 打破了 lhs_MAE_min 的强相关性**: V1 中 Spearman r=0.858（lhs_MAE_min 是最强预测因子），V2+none 中降到 r=0.279。这是因为 V2 的定向采样成功修复了高 lhs_MAE_min 突变体（cdc20_ts 家族 MAE 从 1.63 降到 0.04），使得原本"远距离=高误差"的规律不再成立。

### 10.2 关键诊断：初始训练集大小导致严重欠训练

**这是 mutant_aware AL 失败的根本原因。**

从 `utils/al_callback.py` 的 `on_train_start` 方法（第 148-222 行）可以看到:

```python
def on_train_start(self, trainer, pl_module):
    # 所有 AL 策略都执行初始化 (none 已在外层过滤)
    if self.strategy == 'none':
        return  # ← V2+none 在这里直接返回，使用全量数据

    # ... K-Means 初始选择 ...
    dm.train_dataset_lhs = TensorDataset(
        full_X[selected_idx],  # ← V2+mutant_aware 仅用 2000 样本
        full_P[selected_idx],
        full_Y[selected_idx]
    )
```

- **V2+none**: `al_strategy='none'` → AL callback 在 `on_train_start` 直接返回 → **使用全量 V2 数据集（~65,000 LHS 样本）**
- **V2+mutant_aware**: `al_strategy='mutant_aware'` → AL callback 执行 K-Means → **仅用 2,000 样本开始训练**（仅占全量 3%）

### 10.3 训练动态推演

基于 `al_trigger_epoch=10`、`al_num_add=500`、`best_epoch=12` 推演:

| 阶段 | Epoch | 训练集大小 | 事件 |
|------|-------|-----------|------|
| 初始化 | 0 | 2,000 | K-Means 选取 2000 样本，模型开始训练 |
| 第 1 轮 AL | 10 | 2,500 | 评估 Real Mutant MAE → 加载 atlas → 计算 priority → 生成 ~500 定向样本（聚焦 cdc20_ts 等） |
| **最佳 checkpoint** | **12** | **2,500** | val_loss=0.0664（此后不再改善） |
| 第 2 轮 AL | 20 | 3,000 | 又加 500 样本 |
| ... | ... | ... | 每 10 epoch 加 500 |
| 第 19 轮 AL | 190 | 11,500 | 累计 2000+19×500=11,500（仍仅占全量 18%） |
| 训练结束 | 200 | 12,000 | 远未达到 V2+none 的 ~65,000 |

### 10.4 atlas 加载状态推断

虽然没有 stdout 日志（训练输出未重定向到文件），但从以下证据可以推断 atlas **成功加载**:

1. **eval 中的 T-前缀样本分布**: 1275 个 T-前缀测试样本覆盖了 cdc20_ts (73,78,79,74,85,71,75,102)、cdh1 (34,40,36,41,42,46,32,21,106,116,119,120,121,122,118)、CLB1_clb2 (47,48,52,111) 等家族，与 atlas 中 lhs_MAE_min 最高的突变体高度重合
2. **V2+mutant_aware 的 cdc20_ts MAE 从 1.63 降到 0.27**: 如果 atlas 未加载（降级为 rgs），AL 仍会聚焦高 MAE 突变体，但 priority 加权不会如此集中地指向 cdc20_ts
3. **没有降级为 rgs 的证据**: rgs 策略按当前 MAE 排序，而 mutant_aware 按 atlas lhs_MAE_min + density + current MAE 三因子加权。V2+mutant_aware 的 cdc20_ts MAE=0.27（而非 V2+none 的 0.04），说明 AL 的 5% 扰动采样确实聚焦在 cdc20_ts 邻域

### 10.5 模型 Collapse 验证

**发现: V2+mutant_aware 和 V2+none 均存在 T-前缀样本的"模型 collapse"现象**

T-前缀测试样本是 V2 数据集的定向采样测试集（如 73_cdc20_ts_LHS_T238），每个基础突变体有 50~56 个 5% 扰动的变体。检测到 12 个基础突变体的 MAE range < 1e-4（即所有变体的预测几乎完全相同）:

| 突变体 | n | V2+none MAE | V2+none std | V2+mutant_aware MAE | V2+mutant_aware std |
|--------|---|-------------|-------------|---------------------|---------------------|
| 78_cdc20_ts_mad2 | 56 | 0.032 | ~0 | 0.295 | ~0 |
| 34_cdh1_KO | 55 | 0.036 | ~0 | 0.125 | ~0 |
| 73_cdc20_ts | 53 | 0.047 | ~0 | 0.362 | ~0 |
| 26_cln1_cln2_cln3_apc_ts | 53 | 0.028 | ~0 | 0.102 | ~0 |
| 40_cdh1_cdc6_42_49 | 52 | 0.049 | ~0 | 0.184 | ~0 |

**解读**: "collapse" 不是 bug，而是**预期行为**——5% 参数扰动不应显著改变轨迹，模型预测相同输出是正确的泛化。关键差异是:
- V2+none collapse 在 **低 MAE**（0.03~0.05）→ 模型学到了正确的轨迹
- V2+mutant_aware collapse 在 **高 MAE**（0.10~0.36）→ 模型欠训练，预测了错误的常数轨迹

## 12. V2 数据集根因验证

### 12.1 V2 数据集设计意图

> 来源: `budding_yeast_v2/data/lhs_v1_origin_v2.py` 第 753-801 行

V2 数据集通过 `generate_targeted_lhs_tasks()` 函数，对 4 个家族做定向扩展采样:

| 家族 | 突变体数 | 采样模式 | 关键参数 | 每突变体采样数 | 扰动幅度 |
|------|---------|---------|---------|--------------|---------|
| **cdc20_ts** | 8 | boundary | ks20p=0, ks20pp=0 | 500 | 10% |
| **CLB1_clb2** | 5 | boundary | ksb2p=0, ksb2pp=0 | 500 | 20% |
| **cdh1** | 10 | anchor | init_CDH1T=0, init_CDH1=0 | 500 | 10% |
| **low_lhs_count** | 4 | density | (N_LHS 不足补足) | 300 | 10% |

三种采样模式:
- **density**: 在原参数邻域做局部 LHS 扰动，增加密度（与 RGS 一致）
- **boundary**: 扩展连续参数的采样范围到 0 边界，覆盖彻底敲除参数（如 ks20p=0）
- **anchor**: CDH1T/CDH1 使用锚点值 (0.0, 0.0) 强绑定，其他参数局部扰动

## 14. 改进建议

### 14.1 mutant_aware AL 的修复方向

#### 建议 1（最高优先级）: 增大初始训练集或改为全量预热

**问题**: `al_initial_train_size=2000` 导致模型从 3% 数据开始训练，严重欠训练

**修复方案**:
```python
# 方案 A: 大幅增大初始训练集
al_initial_train_size = 50000  # 接近全量，让模型先学完基础

# 方案 B: 先全量预热再切换到 AL（两阶段训练）
# 阶段 1: 前 100 epoch 用全量数据训练（等同 v2+none）
# 阶段 2: 100 epoch 后启用 AL，定向加样
```

**预期收益**: 避免 LHS Test 性能暴跌（0.185 → 接近 0.087），让 AL 的定向采样在已有良好基础的前提下"锦上添花"而非"雪中送炭"

#### 建议 2: 推迟 AL 触发 epoch

**问题**: `al_trigger_epoch=10` 时模型仅训练了 10 epoch（2,000 样本），Real Mutant MAE 评估极不准确

**修复方案**:
```python
al_trigger_epoch = 100  # 等模型基本收敛后再触发 AL
# 或: 基于 val_loss 收敛判断，当 val_loss 连续 20 epoch 不改善时触发
```

#### 建议 3: 增大每轮 AL 的新增样本数

**问题**: `al_num_add=500` 每 10 epoch 才加 500 样本，200 epoch 累计仅 10,000 样本（远不够）

**修复方案**:
```python
al_num_add = 5000  # 每轮加 5000，200 epoch 累计 100,000
```

#### 建议 4: atlas 引入方式改为"软引导"而非"硬聚焦"

**问题**: 当前 priority 公式 `0.5×norm(lhs_MAE_min) + 0.3×density + 0.2×norm(current_mae)` 过度聚焦 cdc20_ts（lhs_MAE_min ≈ 1.7），导致其他家族被忽略

**修复方案**:
```python
# 方案 A: 降低 atlas 权重，增加 diversity
priority = 0.3 * norm(lhs_MAE_min) + 0.2 * density + 0.1 * norm(current_mae) + 0.4 * diversity_score

# 方案 B: 对 atlas top-K 做"采样配额上限"（已有 30% 上限，可进一步收紧到 10%）
max_per_mutant = rgs_budget * 0.10  # 单个突变体最多占 10%（当前 30%）
```

#### 建议 5: 增大 perturbation 幅度

**问题**: `al_perturbation=0.05`（5%）生成的定向样本过于接近目标突变体，导致模型 collapse（所有变体预测相同输出）

**修复方案**:
```python
al_perturbation = 0.15  # 15%，与 V2 数据集的 boundary 采样一致
# 或: 渐进式扰动，早期 5%，后期扩大到 20%
```

### 14.2 V3 数据集的进一步改进

#### 建议 6: 对 62_GAL_CLB2_db 做定向采样

**问题**: V1 和 V2 中 62_GAL_CLB2_db 的 MAE 均为灾难级（1.28 / 1.84），是 V2 数据集唯一未覆盖的 Pattern C 灾难点

**修复方案**:

'GAL_CLB2_db_family': {
    'mutants': ['62_GAL_CLB2_db', '60_CLB2_db_clb5', '55_CLB2_db', '124_APC_A_GAL_CLB2'],
    'num_per_mutant': 500,
    'perturbation': 0.15,
    'mode': 'density',  # 先用 density 增加密度
}
```

#### 建议 7: 对 CLB2_db 家族做 boundary 采样

**问题**: V2+mutant_aware 中 CLB2_db 家族 MAE=0.722（+120%），说明 CLB2_db 参数空间可能需要 boundary 采样

**修复方案**:

    'mutants': [...],
    'mode': 'boundary',
    'boundary_params': {'ksb2': 0.0, 'ksb2p': 0.0}  # 需分析 62_GAL_CLB2_db 的突变规则
}
```

#### 建议 8: cdh1 家族的 anchor 采样优化

**问题**: anchor 采样（init_CDH1T=0）对部分 cdh1 突变体有效（34_cdh1_KO: -84%），但对部分无效（46_swi5_cdh1_GAL_SIC1: +64%）

### 14.3 评估层面

#### 建议 9: 修复 Rel_L2 数值爆炸

V2+none 仍有 25 个 Rel_L2 > 100 的突变体（与 V1 相近），主要因 CDH1T=0 导致 ||true - mean(true)|| ≈ 0

```python
# 建议: 改为相对 RMS 误差或加入 epsilon
rel_l2_stable = ||pred - true|| / (||true - mean(true)|| + epsilon)
# epsilon = 0.1 或改为只在方差 > threshold 的变量上计算 Rel_L2
```

#### 建议 10: 增加 Pattern-aware 评估

在全局指标中分 Pattern 报告 Rel L2 / MAE / Corr，单独跟踪 Pattern C 灾难突变体（62_GAL_CLB2_db）作为模型改进的"金丝雀指标"
