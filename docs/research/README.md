此文件是稳定导航和接手规则，不保存另一份实验流水账。适用于能访问同一服务器文件系统的agent；另一台机器/另一份checkout必须另外同步本目录记录，聊天历史与Git仓库本身不会自动同步机械盘结果。

## 唯一研究记录与当前状态

- [当前状态JSON](current_state.json)：最新完成编号、结果、是否仍运行、后续建议、正式协议。

本目录记录是单一事实来源，禁止在平台各自的memory中维护互相冲突的“最新状态”。本目录的研究记录、状态与证据索引可以随仓库纳入版本管理；机械盘原始实验结果不自动随Git同步。当前未自动提交任何更改。

## 每次接手的最低阅读顺序

1. 读根目录[AGENTS.md](../../AGENTS.md)，确认本轮用户授权及服务器/生物规则限制。
2. 读本目录current_state.json和研究记录首页快照，再读最新完整条目与链接报告。历史“下一步”可能已经执行或被否定，不能照抄重跑。
3. 核查相关批次completion/status/tasks、tmux及本任务进程；状态JSON不是实时进程监控器。只读当前规则下允许的信息，不擅自开放审计/test/real。
4. 核对`git status`、关键数据/配置/源码身份以及相关实现；保留其他人的未提交改动。运行中的sources身份范围禁止热改。
5. 在动手前说明要继续哪个研究编号、哪些事实已确认、准备改变什么、是否会启动训练。接手文件不是新长跑授权。

## 写回与证据要求

- 新研究顺延编号，不覆盖旧结果；运行前记录假设、候选动作、对照、预算、信息权限、停止条件、入口和输出位置。没有事前门槛就如实标开放诊断，不倒填“预注册”。
- 完成后同步更新条目状态、首页索引/快照、current_state.json、证据清单；失败/中止也写，不能只写成功案例。
- `last_updated_by`填写实际平台/人员，时间使用Asia/Shanghai；记录运行标识和输出，切换平台先更新状态。多个agent同时做研究时明确任务归属，不共同改同一运行源码或同一记录；当前文件没有实现分布式锁，不能假定自动防冲突。
- 原始config/有序样本ID/checkpoint/日志留在单项实验目录；跨实验解释进入summary。不要复制轨迹、把短程诊断与五轮正式成绩混排，或把两训练RNG说成两独立split。
- 报告改变结论时写“被哪条新证据修订”，保留旧原报告；未解决的混杂因素和测试集适配风险必须显式记录。
- 已有real被反复用于开发，不声称新盲测；不能按real逐例误差决定下一批查询。停止的分支不可仅因换平台而恢复。
