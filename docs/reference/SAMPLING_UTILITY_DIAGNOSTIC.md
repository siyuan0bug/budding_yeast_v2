# 采样机制诊断：错误大小与训练收益

这是完全可读训练侧标签的机制诊断，不是新baseline或仅查询256标签的AL。复用当前mutation完整池及共同初始2000条模型；不调用ODE，不修改生物规则，不读取real或正式合成validation/test轨迹。

## 独立角色

从训练侧候选输入/metadata划分：

- 已训练初始2000条：严格核对已有checkpoint数据哈希。
- 候选短名单4096条：独立随机选取，允许读取全部真实轨迹计算当前模型误差。
- 选择反馈集512条：用来比较短程试训的批次收益。
- 最终检查集512条：批次选择锁定之后才推理，只报告最终效果。

反馈/最终检查的模块、mutation模式和mdt完整背景互不重叠；均不属于初始训练背景；全部排除于训练候选短名单。每个保留背景最多2条。划分只使用输入和mutation元数据，不依据输出或预测误差。

完整标签访问量为7120条（含初始2000条），不能称为仅新增256条的标签效率实验。数据仍只保存在源池，各训练清单只记录源引用和有序ID。

## 对照与试训

固定8个候选批次，每批256条：1批随机、1批初始模型真实归一化Relative最高、6批独立随机。高误差批次是4096条短名单中的TopK，不是整个90k训练侧的全局TopK。

每批与相同初始2000条合并，从同一checkpoint开始，使用相同模型/训练随机流，试训40个optimizer更新。另有原2000条继续训练40步对照。仅按反馈集归一化Relative最低选择一批，随后锁定选择；不因最终检查结果重新选批次。

最终比较4组：原2000条继续训练、随机追加、真实高误差追加、反馈试训选批追加。全部重新从原checkpoint起步，固定400步，训练RNG分别42/123，批次选择不随RNG重选。相同数据的组复用确定性训练结果并明确标注。两套训练RNG不等同于两个独立数据划分的正式多seed实验。

公共配置：FNO容量/损失沿用checkpoint，batch128、AdamW固定LR=1e-4、梯度裁剪1、统计冻结于初始checkpoint。仅为隔离机制的增量训练诊断，正式冷启动/逐轮refit协议不变。最终固定更新评测，不取反馈或最终检查best。

## 预先声明的解释边界

- 高真实误差比随机稳定改善超过2%：支持继续排查原物理/响应评分没有找准有用误差的可能性。
- 高真实误差不优于随机：说明单纯找难样本在此增量训练协议下不够，不能据此推断整个系统无法通过采样改善。
- 反馈选批比随机在两套训练RNG均改善超过2%：提示实际训练收益信号值得进一步研究，仍需独立数据划分和预算公平的正式实验。
- 试训反馈改善不能迁移到最终检查：应检查短期收益估计和反馈泛化，不能拿反馈结果冒充独立测试收益。

主要诊断为同一冻结归一化下逐样本逐变量Relative；同时报告物理MAE/MSE/Relative/相关性及逐样本误差。所有结果仅用于内部机制分析，不与正式10k的real榜单混排，也不声称论文创新。

CLI：`scripts/analysis/probe_sampling_utility.py`。单GPU顺序执行、I/O读取串行，使用公共训练/归一化/评测组件；标签在一个有界联合读取中载入内存，不反复解压碎片化累计清单。

输出：外部`resource_profiles/sampling_utility_probe_*/`，含protocol、候选误差、每个试训的反馈指标、锁定选择记录、两套训练RNG的最终检查指标/权重和完整报告。关键阶段日志带时间戳，W&B关闭或离线。

## 数据量参考：随机1万与嵌套3万

研究目标仍是real mutant泛化；内部合成探针用于定位数据/模型瓶颈，不能把合成指标改善直接等同于real性能改善。

`scripts/analysis/probe_data_volume.py`复用已完成的Random/seed42最终1万条模型，仅新增训练随机3万条参考组。3万条保留原1万条的顺序，再从训练侧随机补2万；原先内部探针ID不再加入新增数据。独立随机留出1024条输入，再保留512条未见完整mutation/mdt背景；两组都不得进入3万训练，后者的整个背景也不进入训练。全部基于输入选定，不按误差选样。

3万条从头训练，使用原1万最终轮相同的模型初始化seed、FNO容量、batch128、学习率、200epoch、10epoch预热、余弦调度、Relative eps0.01及合成来源验证集归一化loss选best。归一化各自在对应训练集上重新拟合一次。独立比较使用物理指标，另用原1万训练统计提供共同坐标下的归一化Relative；各模型自己的归一化loss不能直接跨组排名。3万组更新次数更多，是数据可用性参考，不能作为同查询/算力预算采样方法优胜证据，也不是理论性能上界。

按物理目标轨迹时间L2范数分为精确0、(0,0.01]、>0.01三组，阈值沿用主Relative分母保护尺度。报告分组误差及对总Relative的贡献，不修改loss、主指标或样本。real/正式test轨迹不读取；来源合成验证集只参与既定checkpoint选择。

上述信息条件针对训练和内部诊断阶段。两组best固定之后，可以单独进行real参考的只读终评，并将checkpoint哈希、评测阶段和逐株结果另存；不根据该终评回溯选epoch或重训。既有real参考已经反复用于开发诊断，不能称为新的盲测。

新增结果统一位于`experiments/budding_sampling/fno/mutation/random_volume_reference_30000/<profile>/seed_42/`，包含train.log、只引用源池的data清单、training模型/history/loss、私有恢复状态和eval内部探针分解。跨1万/3万汇总位于同一结果根的summary目录。`--resume`只允许相同源码/数据/配置身份，通过公共训练服务恢复；不覆盖旧实验。

## 近似等更新次数控制

`scripts/analysis/probe_compute_control.py`复用上一个诊断固定的1万训练ID、两组探针、来源合成验证集及模型初始化seed，从头训练新的1万参考，不从200epoch权重续训。batch128时，每epoch分别79步（1万）和235步（3万），因此最近整数预算为595epoch=47005步，与3万200epoch的47000步只差5步；预热30epoch=2370步，与3万组2350步近似对齐。峰值/最低LR、weight decay、模型、损失均沿用，余弦调度按epoch离散，不能声称每一步完全一致。

归一化仅拟合原1万训练集，并与旧1万checkpoint统计核对。先按合成验证归一化loss选best，再评测相同内部探针和real参考；只在终评绘制real预测图。新结果位于`fno/mutation/random_update_reference_10000/<profile>/seed_42/`，summary三方并列1万200epoch、3万200epoch及1万595epoch。前两组结果及权重不覆盖。比较近似同更新的1万与3万时，仍包含各自训练统计的差异，不是排除了所有因素的纯数据量因果效应。
