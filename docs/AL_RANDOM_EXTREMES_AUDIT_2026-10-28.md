# Random AL大值样本与FNO误差审计（2026-10-28）

**结论：确有大值，但现有证据不足以把badcase归因于取消2倍阈值；也不能直接归因于FNO容量太小。** 大值会改变归一化和任务难度，最终训练中未出现它们包揽损失的现象。局部突变响应、事件时序、ORI累积误差更值得分别检查。没有修改采样、过滤、模型、损失或正在运行的实验。

## log1p＋Z-score是否被极值拖垮

用全部70000 train拟合，与只用旧规则内58468 train拟合做**统计量反事实比较**，未进行过滤后重训：

|---|---:|---:|---:|
| CLN2 | 0.731 | 0.615 | 1.189 |
| CLB2 | 0.745 | 0.606 | 1.229 |
| SIC1 | 0.817 | 0.671 | 1.218 |
| CDC6 | 0.795 | 0.685 | 1.159 |
| ORI | 1.732 | 1.619 | 1.070 |
| CDC14 | 0.550 | 0.360 | 1.526 |

CLB2在0～1的范围，完整train编码后跨度log(2)/0.745约0.930个标准差；若过滤后拟合约1.144。数值上可以区分大小值；但相同局部log误差的标准化MSE权重会降到约0.662，即降低约34%。这说明存在重加权影响，并不说明它造成了当前badcase。

抽查最终checkpoint：按六分类×是否超过旧上限分层，每格最多256条，共3005条train；按每格总体数量/抽样数量加权还原70000条总体。旧上限内/外的平均normalized MSE约0.01275/0.01666，Hybrid约0.03412/0.03813；上限外16.47%的样本约贡献18.06%的Hybrid损失。**这是抽样估计，不是精确全量训练损失，也不是参数梯度份额。**

作为另一种辅助诊断，中心常数预测器的原始值平方能量约94.97%来自上限外样本，log1p+Z-score后约33.42%；常数预测器能量不能冒充实际FNO损失。

训练preprocessing与float64精确重算存在CPU float32归约舍入差异：初始10k的mean最大差4.19e-5，直接用Torch 1/2/8线程可复现保存统计量。报告逐轮记录该差异，推理一律使用checkpoint的真实保存统计量；不把重算的float64值替换进模型。

## 能否归因于FNO，下一步怎样验证

当前FNO有3751847个参数条目，复数按两个实数计为7290791个实数自由度，不属于很小的网络。标准FNO含谱卷积、局部分支和非线性；modes=24不是输出严格只能有24个频率的硬上限。结构背景见[FNO原论文](https://arxiv.org/abs/2010.08895)，本项目实际实现见models/baselines/fno.py。现有实测支持“局部条件响应和事件波形仍需改善”，尚不能证明增加width/modes、换模型或恢复过滤就一定更好。

更有解释力的两组受控对照：①同一FNO、相同seed/训练预算/最终有效样本数，对比不过滤与旧规则过滤后补足数量；固定验证、synthetic test和126 real，不能把困难测试样本也删掉。②完全相同训练数据与划分，比较FNO与另一模型。两组分别检查数据域与架构影响；先报告逐株/逐变量/局部响应，不只看一个全局MSE。需要归一化专门消融时，应单独固定数据改变拟合范围，不与删样本混在一个结论里。

本轮未恢复任何阈值，未新跑训练。
